How We Work

Development Workflow

The agreed process for making changes, previewing, and deploying the portfolio site.

📌
Golden Rule
Always preview changes on localhost first before pushing to GitHub or deploying to Vercel. Never deploy without explicit approval. Just ask: "Would you like to push to GitHub and deploy to Vercel?"
1
✏️ Request a Change Start Here

Tell Claude what you'd like to change, add, or create on the site. This could be a new section, a design tweak, a new page, or any update.

  • 💬 Describe the change in plain language, no technical knowledge needed
  • 🖼️ Share a reference or example if you have one
  • 📄 Specify which file or page to update (if known)
2
⚙️ Claude Makes the Change Automated

Claude edits or creates the file(s), then confirms localhost is running so you can preview immediately.

  • 🛠️ File is updated in the project folder
  • 🔁 Local server is verified to be running on port 3000
  • 🔗 Localhost preview link is shared
$ localhost:3000   server already running
3
🔍 Preview on Localhost Your Turn

Open the provided link and review the changes in your browser. Check all pages affected and test on different screen sizes if needed.

  • 🌐 Open http://localhost:3000 in your browser
  • 📱 Resize the window to test mobile responsiveness
  • ✅ Approve, or request further adjustments
4
🐙 Push to GitHub On Approval

Once you're happy with the preview, Claude will commit the changes and push to the portfolio-revamp branch on GitHub.

  • 📁 Changed files are staged and committed with a descriptive message
  • ⬆️ Pushed to ghub-geneva/personal_website → branch portfolio-revamp
  • 🔀 PR #1 is updated automatically with the new commit
$ git add . && git commit -m "your change" && git push origin portfolio-revamp
5
🚀 Deploy to Vercel Goes Live

After GitHub is updated, Claude runs the Vercel production deploy. Your site goes live at genevadaugdaug.com within seconds.

  • ⚡ Vercel CLI deploys directly to production
  • 🌍 Live at https://www.genevadaugdaug.com
  • 🔗 Deploy URL is shared for confirmation
$ vercel --prod --yes
Workflow Rules
🚫
Never Auto-Deploy
Claude will never push to GitHub or deploy to Vercel without your explicit "yes". Always ask first.
👁️
Preview First Always
Every change, big or small, gets a localhost preview link before it goes anywhere near production.
🔗
New Page = New Link
When a new page is created, the direct localhost link for that specific page is always provided.
📦
GitHub Then Vercel
The order is always: commit → push to GitHub → deploy to Vercel. Never skip or reverse the steps.
🔄
Iterate Freely
Request as many adjustments as needed during the localhost preview stage. No limits before approving.
💾
One Commit Per Change
Each approved change gets its own descriptive commit so the GitHub history stays clean and readable.
